# Free acceptance protocol — frozen before implementation

Frozen: 2026-10-16. Scope: the existing Free tracking, reporting, connection, correction and limit promises identified in the October 15 audit. No new paid features, pricing/entitlement changes, purchases or deployments. Existing qualification changes in the backend are a separate, undeployed workstream and must be preserved.

## Decision rule

An A requires every critical acceptance row below to pass on the release candidate, no known material contradiction or lost-record failure in these flows, and release-environment evidence for consent/reconnect, toolbar permissions and notification delivery. Controlled browser tests establish interface behavior, not successful Google authorization or production ingestion. Historical live evidence is identified by date and version; it cannot certify newly changed code. Missing external evidence prevents an unqualified A. A+ additionally requires independent task-based human review of these same flows without coaching, and confirmation after release that the verified behavior survives the real integration. No independent reviewer is currently available. Neither score measures population classification accuracy or hiring outcomes.

## Procedure and provenance

Recover original inputs, scripts, captures and service receipts. Record repository heads and all existing dirty files before editing; hash evidence and relevant baseline source. Reproduce against a fresh current-source build, retaining original audit captures unchanged. Freeze this protocol's hash in the baseline manifest. Implement only reproduced defects or directly demonstrated counterexamples. Save browser traces and raw observations to `.codex_tmp/free-a-20261016/`. Report passing, failing and unavailable separately. Do not silently relax this rubric when an integration cannot be exercised.

Grade functional correctness, usability and accessibility separately. The aggregate grade cannot exceed B+ while a critical release-environment evidence gate is unavailable; an A-ready local result is not a deployed A. Any material false-success or incomplete-report defect caps correctness at C until resolved. This is an explicit editorial acceptance rubric, not a validated numerical scale.
